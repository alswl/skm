# skm 安装动线改版提案

状态：统一小写 `i`、用户级声明默认值和入口带入已实现。完整覆盖列表、从位置撤回和恢复页补路径仍为提案。按标签安装见 UC2。现状以 [TUI Wireflows](tui-wireflows.md) 为准。

## 1. 问题定义

用户通常知道要安装的技能、客户端或仓库中的至少一项。当前技能页用 `i` 打开直接安装面板，用 `I` 打开声明式安装。两个入口都能操作用户级安装，写入结果不同。从技能页发起声明式计划时还无法直接选择任意单个已登记目录。目录页能指定目录，但用户需要重新选择技能。

另一个断点发生在清理时。扫描结果能显示一个链接是否被声明覆盖，但卸载被挡住后，需要另找声明。标签声明可能同时覆盖多个目录，直接撤回会影响接下来在这些目录的恢复。

## 2. 用例与方案比较

| 用例 | 用户要做的事 | 需要看见的结果 |
|---|---|---|
| UC1 | 从 `review` 详情安装到 `api` 的 Codex | 当前技能自动带入。选 `api` 后确认写入一条目录声明和一条链接，完成后原详情显示新位置 |
| UC2 | 把两项技能部署到两个重叠标签 | 预览显示去重后的目录和安装位置，展开才显示路径 |
| UC3 | 临时给用户级客户端安装 Skill，或直接管理已有 Command | 能明确选择仅本机操作。用户级旧面板里的查看、取消安装和修复入口有对应去处 |
| UC4 | 收录已有链接，或清理一个被声明覆盖的位置 | 从该行查看匹配声明、覆盖范围和去除覆盖的可用操作。收录、撤回、卸载分别呈现写入效果 |
| UC5 | 在另一个 checkout 恢复之前的安装 | 从恢复预览找到缺本机路径的目录，设置后重新预览，同一次恢复的结果可逐项查看 |

| 方案 | 用户如何选择 | 好处 | 代价 |
|---|---|---|---|
| A · 延续双入口 | 首先选直接安装或声明式安装 | 旧用法几乎无迁移 | `i` / `I` 仍要靠记忆，跨入口会丢选中的对象 |
| **B · 统一安装入口** | 先定技能和目的地，预览时确认写入效果 | 技能、目录、批量安装汇合，兼容临时用户级安装 | 需要调整旧复选框面板，并统一冲突、确认和结果反馈 |
| C · TUI 默认只提供声明式 Skill 安装 | TUI 主动线都写声明，其他安装从独立工具入口处理 | 规则最少，适合以 Git 恢复为主的场景 | 低成本试装和现有直接安装工作流要换入口，Command 仍需单独处理 |

采用 B 的单入口方向。技能页和目录页用小写 `i` 进入同一个安装流程，各自带入当前选择。对支持声明的 Skill，建议默认勾选「写入安装声明」，预览始终写清会改变什么。用户级 Skill 是否默认写入声明由本机配置决定，只设置一次。预览允许本次改选，常规安装无需经过单独的偏好选择页。首版可以把「仅本机安装」限定在已有用户级目标，目录和标签走已有声明式能力。这样保留用户级试装，也避免为了统一入口扩出一套目录级临时安装。

## 3. 数据和写入边界

- **持久配置沿用现有结构。** 技能、目录 ID 和标签、安装声明继续随库版本化。本机目录路径继续独立保存。安装声明仍由技能、客户端和范围确定。
- **增加页面可用信息。** 安装位置显示盘面状态和匹配的声明来源。匹配关系按需计算，可同时来自目录、标签或别名指向的同一位置。覆盖核验不完整时显示原因并阻塞卸载。
- **安装草稿只在会话内存中。** 记录从哪一页发起、已选技能、目的地和客户端、是否写声明。返回上一步保留选择，确认前按预览执行。无需增加安装历史、归属记录或新配置文件。

## 4. 拟议 Wireflows

**UC1 · 从技能详情安装到一个目录**

```text
[技能详情  review | 安装位置]
  i 安装
  → [选择目的地  用户级 / 目录 / 标签]
     目录 → [搜索已登记目录  › api] → [客户端  ☑ Codex]
  → [预览  review → api / Codex
           新建链接 1     ☑ 写入安装声明 1
           明细 · 执行 · 返回]
  → [技能详情  api / Codex · 已安装 · 目录声明]
```

从目录页按同一个安装动作时预填当前目录，先补技能。批量选择沿用一个预览，默认显示标签和去重后的目录数量、待装及阻塞数。取消回到原页面，返回上一步保留已选项。发生过期时保留选择、重新预览，只有确认后的范围会写入。

**UC2 · 按标签批量安装**

```text
[目录 · 按标签筛选 team] i
  → [安装  目的地已带入 标签 team · 可改]
  → [多选技能  ☑ review  ☑ lint]
  → [目的地  ☑ team  ☑ frontend · 并集 5 个目录（示例）]
  → [选择客户端  ☑ Codex  ☑ Claude Code]
  → [预览  2 项技能 · 2 个标签 · 5 个唯一目录
           新建 / 已装 / 阻塞 · 按需展开路径]
  → [确认] → [回到目录页，保留筛选，查看安装结果]
```

从技能详情也能发起同一动作。`review → i → 按标签 → 选 team、frontend → 选客户端 → 预览`，技能已带入。目录页存在标签筛选时带入该标签，未筛选时可选「当前目录」或「按标签」。标签筛选只提供初始选择，预览以实际勾选的标签为准。

写入的声明保留标签范围。重叠标签命中同一个目录时只安装一次，恢复按届时的标签成员重新计算。预览显示标签、唯一目录数和实际位置数。标签零命中时留在选择页，不进入执行。已有占位或 Git 风险只在预览中按受影响的位置提示。

**UC3 · 用户级试装及旧操作**

```text
[技能详情  review] i
  → [目的地  用户级] → [选现有客户端]
  → [预览  新建链接 1   □ 写入安装声明]
  → [技能详情  用户级 / Codex · 已安装 · 未声明]

[技能详情  安装位置]
  → [选中一个现有位置] → [收录 / 查看声明 / 修复 / 卸载]
```

旧面板的「装」并入统一入口，「看、移除、修复」落到实际安装位置。Command 继续走支持该类型的直接安装路径，页面明确显示仅本机安装。既有链接可通过收录纳入声明，无需重装。界面、帮助和操作菜单只展示小写 `i` 这一条安装动作。

**UC4 · 从某个安装位置处理声明覆盖**

```text
[目录 api 或技能详情 review]
  → [安装位置  api / Codex · 已安装
       覆盖来源  标签 team（命中 8 个目录，示例）]
     查看声明 → [变更预览  当前声明及影响范围]
     确认撤回 → [声明已撤回，链接保留]
     仍有覆盖 → [列出剩余声明]
     全部解除 → [卸载确认  仅所选链接] → [重新扫描]
```

当用户只想让 `api` 退出覆盖时，先展示「从 `api` 移除 `team` 标签」的影响，因为它可能同时影响该目录的其他技能。也可以将原标签声明改为明确目录范围，再预览受影响位置。首版可提供跳转和影响预览，再由用户确认相应的标签或声明变更。无需添加单目录例外规则，也不把撤回与卸载合并成一次写入。

**UC5 · 缺路径的恢复**

```text
[目录 → 恢复声明安装]
  → [预览  待装 · 已满足 · 缺路径 · 冲突]
     选缺路径的目录 → [设置本机路径] → [重新预览]
  → [确认执行] → [恢复结果  逐项查看]
```

## 5. 模块和优先级

| 优先级 | 模块 | 拟议调整 |
|---|---|---|
| 先做 | 技能详情与目录 | 从实际安装位置进入查看、修复和卸载，解释覆盖来源与影响 |
| P0 | 安装 | 统一技能页和目录页的安装入口，保留用户级直接安装能力。单目录可搜索选择，批量计划按标签汇总 |
| P1 | 安装声明 | 从安装行查看覆盖、收录或撤回。恢复预览能直接定位缺路径目录 |
| P1 | 用户级目标 | 保留客户端与路径设置，并在没有可用用户级目标时从安装流程提供设置入口 |
| P2 | 技能库其他动作及任务 | 保持导入、更新、Fork 和任务页独立，逐步统一动作菜单的分组和结果反馈 |

本次优先改 TUI 页面与流转，复用现有扫描、安装计划和确认后复核。声明覆盖的查询需要从目前的布尔标记补成可解释的匹配结果。CLI 已有 `install` 与 `plan/apply`，本方案可沿用这些接口。
